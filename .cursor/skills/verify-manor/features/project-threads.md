# Project threads

A project can have one curated project thread (decided 2026-10-10). The Sessions sidebar holds a `region "Projects"` above the `Sessions` list (`heading "Sessions"`, level 3; on the phone the list holds every session), with one row per project that has a thread (`Open project thread <name>`) and its state on the right: `Waiting on you` while a session question or a result waits, `1 running` while a session it started runs, otherwise an age. The thread is a Single chat, with "Reply…" in its composer and only the status above replies, without a project icon, name or visible model; it writes `preferences.md` and `notes.md`, each reply's writes as one footnote under it (`button "Saved 2 lines to preferences.md · Saved 1 line to notes.md"`, `aria-expanded`, opening to the lines; only `Manor restored …` stays a card of its own), proposes sessions on a card, holds their questions and their Confirm. Sessions it started stay out of the desktop list and show in its bar above the composer (`Open <title> on the right`, `Settle <title>`). Everything since the user's last message that needs nothing from them folds into one line at the end of that stretch (2026-10-17). It holds Session cards that are not a proposal or a Ready result, info notes (an answered question, a report, settled, learnings), a Session's own `notes.md` status writes, and a wake turn that finished quietly (one whose reply ends on a question to the user stands on its own, 2026-10-19). The line is `button "1 Session done · 2 lines in notes.md · learnings from 1 Session"` with `aria-expanded`; it shows one chip per kind of thing that happened (`2 Sessions done` once every Session in it settled, else `1 Session`; `2 written notes`, `1 saved preference`, `1 removed preference`, `1 learning`; the Sessions chip takes the colour of the Session that asks most of the user). A press opens one flat list of filled tiles (no per-item border, no headers at any count), Sessions first, then notes, then learnings, arrival order within a kind: a Session is its thread line on a tile, led by the Sessions mark in its state's colour like every Session line in the thread, never a provider logo or face (`button "Open Session <title>, Working"`, or a done line with the Sessions icon, `<title> · <summary>` and `Confirmed` or `Done`), a quiet wake turn is a note too, its reply one row (`update` mark, first line, opening to all of it) and each line it wrote a row under its file (2026-10-19), a note is `button "<first line> <tag>"` with `aria-expanded`, its tag the file (`notes.md`) or the time, and a press shows its whole text as written with icon and tag on the first line (2026-10-18, the Paper design "Thread bundle states"; evidence in `evidence/thread-bundle-tiles/`; the phone fixture's `Stilte` thread shows `2 Sessions done · 1 written note` with two Confirmed tiles and a note that opens to two lines). A stretch with only one such item shows that item on its own line, without the fold (2026-10-17). A proposal, a Ready result, a running or asking turn, an error note and the thread's replies to the user stand on their own; a still open Session question shows only on its card above the composer. The thread's reply to a question wake that carried only questions and wrote nothing is its advice (2026-10-19): it never draws as a turn, the card shows it under the question as `<project> suggests <advice>`, and once answered the question's row stands right before its answer and opens to the question with `Suggested · <advice>` under it (evidence in `evidence/thread-question-advice/`; `@Smith mock ask:` with no matching preference makes the mock thread advise its first option). The user's next message starts a new line, and an older line stays folded where it stood, so a result that is confirmed later folds into that older line (evidence in `evidence/thread-bundle/`; the phone fixture's `Stilte` thread shows `1 answer · 1 update` and `2 Sessions done` around its Accept card). Consecutive cards stack 8px apart, The user's message and any card under a reply sit 16px lower; a brief from a DM shows its task as the same folded kickoff card a Session opens with (2026-10-12).

## Sub-features

- `pt-create` is `Add a project`, a hidden project from its menu, and the thread opening by itself; `New project…` makes the project first. Being in the Projects list is having a thread (2026-10-14): startup never creates one, so the seeded `Manor` starts hidden.
- `pt-write` is a preference write and its line; the file lands in the spike's memory folder, `/tmp/manor-electron-spike[-PORT]/memory`, at `memory/structured/<slug>/preferences.md` with `owner: project-thread` in its frontmatter.
- `pt-session` is a session card in the thread, Accept leaving the split exactly as it is (2026-10-15; the Session shows in the overview, and `Open <title> on the right` opens it; the phone also lists it), and its bar row.
- `pt-question` is a session question answered by the thread from a preferences line, and one that waits on the thread's card for the user while the session shows `Waiting for a choice in the project thread` with `Open project thread`.
- `pt-result` is the result card in the thread and the session's `Ready <title>` bar row with the card's own two actions (2026-10-14): `Follow up` and `Close` for a report with nothing to commit (meta `Report · N choices open`, `Your call` lines, `Open report`, folding to `Closed`), `Request changes` and `Confirm` for one with files. The bar row is gone while the session runs again. Also the learnings wake. Evidence in `evidence/result-cards/`.
- `pt-brief` is a DM proposal for the project: Accept stays in the DM while the thread starts the session itself; the DM card reads `Running via project thread <name>`.
- `pt-context` is the `Context` door in the thread: `Project folder` with the two thread files first and their last write, and a read-only `User folder`.
- `pt-overview` is the project room: at 1280px and wider the thread opens with `main "Sessions overview"` on the right, three folds `Waiting on you N`, `Working N`, `Settled N` (Settled folded, an empty fold shows its hint), rows `Open <title> on the right` with `Settle <title>` / `Unsettle <title>`. A row opens the session there with a `Sessions` crumb button that goes back, a `Settle` / `Unsettle` button and only the `Session` door. `Close sessions` on the overview or `Close pane` on the session closes the side; the thread's `Sessions` toggle (`button "Sessions"` with `aria-expanded`, last in its header after a hairline) reopens it. The session's crumb is `button "Sessions"` with a back arrow. Its Session panel floats over the transcript instead of docking. Below the split floor the toggle opens `dialog "Sessions overview"` with `Open <title>` rows. The thread's banner title is `button "<project>, edit project"` (icon and name, no badge) and its composer has no `Local checkout` tray.
- `pt-forward` is a follow-up sent on to an existing Session (2026-10-11): the user's thread bubble gains `Sent to` with `button "Open Session <title>"`, the thread's reply carries the same button, no new proposal card appears, and the Session shows their message under `Sent from <project>` and runs it. A settled Session moves out of `Settled N` back to `Working` / `Waiting on you` in the overview.
- `pt-remove` is right-click `Hide project`: refused while a session it started is open, otherwise the thread archives and stays the project's (2026-11-12), the project returns to the `Add a project` menu and its memory files stay byte-identical (evidence in `evidence/project-hide/`). The hidden thread is in no list, `Archived N` included, and picking the project in `Add a project` opens the same thread with its earlier messages (evidence in `evidence/project-hide-keeps-thread/`).
- `pt-calm` is the calm thread (2026-10-11): a proposal card without the project badge; an accepted Session as one line `button "Open Session <title>, Working"` (or `, Waiting on you`, the overview's word); a Ready result as the full card with Confirm; a done one as one line with its outcome (`Done`, `Confirmed` for a confirmed result, or once Git shows its commit or merge landed `<title> · N files` with `Committed` or `Merged into main`, 2026-10-19). A finished turn's copy and feedback icons and its `Worked for <time>` line show on hover or focus only, on every turn; the line names the model only in its tooltip (2026-11-11). Scenario and before/after shots in `evidence/project-thread-calm/`.
- `pt-bundle` is the folded line above (2026-10-17). In a Session started by the thread, `mock status: <line>` writes its `notes.md` status line through the real `set_session_status`; the same text twice writes nothing, and the spike HOME keeps the file across launches, so vary the text.
- `pt-overview-memory` keeps each thread's three folds and Settled page count for the app session. Settled starts with 20 rows and shares the sidebar's `Show N more` row. A Session visit, breadcrumb return, or chat switch keeps the folds and expanded count. The compact popover reads the same state.

## How to get to it (user POV)

- Sessions door, `Add a project`, pick the project. The thread opens; its row sits under Projects.
- In the thread: `mock preference: <line>`, `mock replace preference: <old> => <new>`, `mock remove preference: <old>`, `mock start work Smith: <task>`, then Accept (choose `Multiple` under Options for a goal session). Manor ends each written preference with its date and refuses a line past 160 characters, date included; `<old>` matches with or without that date.
- A card nobody leads: `mock start work nobody in <project name>: <task>` in the thread names no executor. Without a Session persona whose id is the default one, the card has no lead: Options shows Multiple disabled with its reason (`Add a session agent to run Multiple` when no Session persona exists), and Accept runs it as Single.
- A card with a lead and a supporting persona: `mock start work Marlow with Smith: <task>` (Marlow's allowlist holds Smith). Deleting Smith afterwards leaves the card with Marlow's face only; an id the roster no longer resolves draws no face.
- In the session: `@Smith mock ask: <question> | <a> | <b>` asks through the real broker; a preferences line naming option `<a>` lets the thread answer itself. `@Smith mock goal: <result> | <limitation> learn: <preference>` reaches the goal with a learning.
- In the Marlow DM: `mock start work Smith: <task>`, Accept.
- In the thread, after a Session exists: `mock send to <Session title>: <follow-up>` forwards through the real `send_to_session`. Settle the Session first (overview `Settle <title>`) to see it reopen.

## Driving it with control-manor

Preconditions: spike healthy, start from `home`, a fixture repo linked to `Manor` the way `session-changes.md` does it (the result commits there). To fill a session's composer while the thread holds the left pane, narrow the window below the split floor with `resize --width 1000 --height 800`; the bar's `Open <title> on the right` then opens the session alone. A room session opens on its transcript alone (2026-10-11): its `Session` door is the second one in the banner (`--role button --name Session --exact --within banner --nth 1`), the panel floats over the transcript, and `Hide session` closes it again. It is the thread's own panel that floats over the Accept button at the split width: `click --role button --name "Hide session" --within banner` first, and send with `press --key Enter`.

- `click --role button --name "Add a project" --exact`, `click --role menuitem --name Manor --exact`; `snapshot --aria` shows `button "Open project thread Manor"`.
- In the thread: `fill --composer --value "mock preference: Hoeken zijn altijd rond, nooit vierkant"`, Enter; the reply carries a `button "Saved 1 line to preferences.md"` footnote. `mock note: <line>` writes notes.md, and `&&` writes several lines in one turn.
- `fill --composer --value "mock start work Smith: Exportknop toevoegen. Done when it exports."`, Enter, `click --role button --name Options --exact`, `click --role tab --name Multiple --exact`, `click --role button --name Accept --exact`; the thread and overview stay as they were and the card folds to `Open Session <title>, Working`.
- Session: `@Smith mock ask: Ronde of vierkante hoeken? | Rond | Vierkant` is answered from preferences (`Answered from preferences.md: Rond` in the thread). `@Smith mock ask: Welke kleur krijgt de knop? | Blauw | Groen` waits: the row reads `Waiting on you`, `click --role button --name "Open project thread" --exact`, `click --role radio --name Groen --exact`.
- `mock report: <result> choices: <title> = <option> / <option>*; …` reports without writing a file, a result with nothing to commit; `*` marks the recommended option, and `choices:` works after `mock goal:` too. `Open report` on the card opens the session scrolled to the report message.
- `@Smith mock goal: Exportknop werkt | geen beperking learn: Knoppen krijgen geen iconen`; in the thread `click --role button --name "Confirm <title>" --exact` (hide the Session panel first); `git -C <fixture repo> log` shows `Mock result`.
- Single result (2026-10-11): accept under `Single` (`Worktree` is ticked by default, beside Reject; untick it to run in the shared checkout). In the session `mock code edit: export const x = 1`, then `mock goal: <result> | <limitation> shots: <png>,<png>,<png>` is refused in the call (`Not reported as Done: …`) until `review subagent gpt-6.1-sol high: review the current diff` has ended; send the goal again. The thread's card shows `list "Screenshots"` with `Enlarge <name>` buttons; the viewer is `dialog "<name>, 1 of 3"` with `Previous image` / `Next image` and the arrow keys. Confirm folds it to `<title> · 1 file` with `Merged into main`, settles the Session and removes its worktree and `manor/*` branch. An untracked `mock-result.md` in the linked folder before Confirm gives `Merge blocked` with `status "The fast-forward into main was refused."`, `Open Session` and `Retry`; delete the file and press `Retry` to land it under the same Confirm. Appending to the worktree's `mock-result.md` first replaces Retry with `mock-result.md changed since Confirm. Request a new result in the Session.` Evidence in `evidence/merge-retry/`. Any PNG under 4 MB outside the spike HOME's private folders, or inside the Session's own worktree, works as a shot; a spike screenshot does. The spike keeps worktrees outside its HOME, so to prove a shot from inside one (the maintainer's layout, `~/.manor/worktrees`) launch with `MANOR_WORKTREES_DIR=/tmp/manor-electron-spike-<port>/home/.manor/worktrees`.
- `codex background 30s: npm run build` (or `native background 30s: <task>`) in a session ends its turn with the work still running; the overview row stands under `Working` until it finishes or `Stop` ends it, then under `Waiting on you`.
- `send native helper` in a thread-started session keeps a turn running for about 12s, long enough to read `1 running` on the project row.
- Hide: `click --role button --name "Open project thread Manor" --button right`, `click --role menuitem --name "Hide project" --exact`.
- Overview memory: seed more than 20 settled thread-started Sessions on the isolated fixture. Open `Settled N`, capture its 20 rows and `Show 20 more`, open a row and return through the banner's `Sessions` crumb. Capture Settled still open. Click `Show 20 more`, capture 40 rows and the next page label, and repeat the round trip. Switching to Agents and back also keeps 40. Narrow to 1000px and repeat through the `Sessions` toggle to cover the compact popover. Capture ARIA trees with screenshots so row counts can be checked.

## Gotchas

- The thread has no session bar above its composer (2026-10-11); `Open <title> on the right` is the overview's row, still best clicked `--within main --within-name "Sessions overview"`. A card-started Session has no `Local checkout` tray; a plain one and the New session draft keep it.
- A Session whose transcript says `mock slow outcome` makes the mock outcome take 6s, so Settle can be checked with the outcome still pending: the row moves at once and the `… settled.` note gains its outcome after the delay.
- `fill --composer` hits the thread's composer in the room; narrow to `--width 1000`, open the session from the `Sessions` toggle's popover and send there, then widen.
- Saving `Edit project` while a thread-started session waits on a question stayed on `Saving…` (seen 2026-10-10); link a folder before opening the thread.
- `fill --composer` takes the first visible composer, which is the left pane in a split; there is no pane selector.
- The memory store resets on every launch: the folder link, the thread and its sessions are gone, while the files under the spike HOME stay.
- A thread-started session is in the desktop list only while its project is hidden; on the phone layout (390px) it is listed with `via project thread`.
- The mock echoes a thread wake's prompt in its reply, which makes those replies long; the wake line itself stays one line.
- Two goal Sessions in the shared checkout both write `mock-result.md`; Confirm the first before the second reaches its goal, or Confirm fails with `The files changed after the result was published`.
- A Multiple session's Ready card showed only after the next directory change in the thread (seen 2026-10-11, before and after the calm-thread change); accepting another card brings it in.
- `launch --fresh` reuses chat ids but keeps `/tmp/manor-electron-spike-<port>/worktrees`, so a worktree Accept fails with `Manor could not read that worktree`; remove that folder before a fresh worktree run (seen 2026-10-19).
